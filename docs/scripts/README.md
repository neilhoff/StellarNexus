# StellarNexus Scripts

Automation scripts for project setup, deployment, and user management.

## Overview

These scripts handle the operational aspects of deploying and managing StellarNexus sites. They're designed to be run in sequence during initial setup, then individually as needed for ongoing maintenance.

## Scripts

### [Onboard](./onboard.md)

**Purpose**: Initial project setup when creating a new site from the template.

**What it does**:
- Updates project metadata (name, description, author)
- Configures AWS profile and region
- Sets up authentication credentials (Turso, Resend)
- Optionally bootstraps initial super-admin user
- Verifies development environment

**When to use**: Once per new project, right after cloning the template.

```bash
npm run onboard
```

---

### [Bootstrap Users](./bootstrap-users.md)

**Purpose**: Create the initial super-admin user for a new deployment.

**What it does**:
- Creates a user with `["user","super-admin"]` roles
- Hashes password using bcrypt
- Creates an initial session (7-day expiry)
- Works across all environments (testing, staging, production)

**When to use**: Once per environment after initial deployment.

```bash
# Local development
node scripts/bootstrap-users.mjs

# Staging
node scripts/bootstrap-users.mjs --env staging

# Production
node scripts/bootstrap-users.mjs --env production
```

---

### [Setup Environment Variables](./setup-env.md)

**Purpose**: Configure Lambda environment variables for all environments.

**What it does**:
- Sets `ARC_APP_SECRET`, `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`, `RESEND_API_KEY`
- Stores in `preferences.arc` (testing) or AWS SSM (staging/production)
- Auto-generates secure secrets when needed
- Validates and confirms before writing

**When to use**: 
- After onboarding (testing)
- Before deploying to staging/production
- When rotating secrets

```bash
# Local development
node scripts/setup-env-testing.mjs

# Staging
node scripts/setup-env-staging.mjs

# Production
node scripts/setup-env-production.mjs
```

## Typical Workflow

### New Project Setup

```bash
# 1. Clone template and install dependencies
git clone <template-repo> my-project
cd my-project
npm install
cd client && npm install && cd ..

# 2. Run onboarding
npm run onboard

# 3. Set up local environment variables
node scripts/setup-env-testing.mjs

# 4. Bootstrap super-admin user
node scripts/bootstrap-users.mjs

# 5. Start development
npm start
```

### Deploy to Staging

```bash
# 1. Set up staging environment variables
node scripts/setup-env-staging.mjs

# 2. Deploy to AWS
npx arc deploy

# 3. Bootstrap staging super-admin
node scripts/bootstrap-users.mjs --env staging
```

### Deploy to Production

```bash
# 1. Set up production environment variables
node scripts/setup-env-production.mjs

# 2. Deploy to AWS
npx arc deploy --production

# 3. Bootstrap production super-admin
node scripts/bootstrap-users.mjs --env production
```

## Script Dependencies

```
onboard.mjs
  └─> bootstrap-users.mjs (optional, can be run separately)
  └─> setup-env-testing.mjs (optional, can be run separately)

setup-env-testing.mjs
  └─> Creates preferences.arc (if needed)

setup-env-staging.mjs
  └─> Requires AWS credentials
  └─> Requires app deployed at least once

setup-env-production.mjs
  └─> Requires AWS credentials
  └─> Requires app deployed at least once

bootstrap-users.mjs
  └─> Reads from preferences.arc (testing)
  └─> Or fetches from AWS SSM (staging/production)
```

## Environment Variable Flow

```
Local Development:
  setup-env-testing.mjs → preferences.arc → arc sandbox → Lambda process.env

Staging/Production:
  setup-env-staging.mjs → AWS SSM → arc deploy → Lambda process.env
  setup-env-production.mjs → AWS SSM → arc deploy → Lambda process.env

Bootstrap Users:
  testing: preferences.arc → Turso database
  staging/production: AWS SSM → Turso database
```

## Security Considerations

### Secrets Management

- **Local**: `preferences.arc` is gitignored, never committed
- **Staging/Production**: Stored in AWS SSM Parameter Store (KMS-encrypted)
- **Client .env files**: Frontend-only config, no backend secrets

### Access Control

- **AWS credentials**: Required for staging/production scripts
- **IAM permissions**: `ssm:PutParameter`, `ssm:GetParameter` for SSM access
- **Database access**: Turso credentials stored securely, not in client code

### Best Practices

1. **Rotate secrets periodically** - Re-run setup scripts with new values
2. **Use strong ARC_APP_SECRET** - Minimum 32 bytes, auto-generated by scripts
3. **Verify before deploying** - Check `arc env` output before `arc deploy`
4. **Audit super-admin users** - Track who has super-admin role in each environment

## Troubleshooting

### Scripts fail with "command not found"

Ensure Architect CLI is installed:
```bash
npm install -g @architect/architect
```

### AWS permission errors

Verify credentials and permissions:
```bash
aws sts get-caller-identity
aws ssm describe-parameters
```

### Database connection errors

Check Turso credentials:
```bash
turso db show <db-name>
turso db tokens create <db-name>
```

### Variables not available in Lambda

Redeploy after setting variables:
```bash
npx arc deploy          # staging
npx arc deploy --production  # production
```
